# transition-review

건축직 채용연계형 인턴(총 14명) 정규직 전환 역량평가 사이트.
평가자(현장소장/공사책임자/멘토/동료, 총 4인/인턴)가 사번으로 접속해 배정된 인턴만 평가하고,
관리자는 진행 현황·인턴별 원페이지 리포트·전체 엑셀을 확인합니다.

## 구조

```
index.html    평가자 화면 (사번 로그인 → 배정 목록 → 평가서 작성)
admin.html    관리자 화면 (접속코드 로그인 → 진행 현황 → 리포트/엑셀)
report.html   인턴 1명에 대한 4인 평가 종합 리포트 (인쇄/PDF 저장 가능, 1~2쪽)
app.js / admin.js / report.js   각 화면 로직
rubric.js     평가 문항(5개 영역, 4점 척도 행동기준) — 개인정보 없음, 공개 저장소에 안전
style.css     공통 디자인
config.js     Apps Script 배포 URL을 넣는 설정 파일
apps-script/Code.gs   백엔드(Google Apps Script) 코드
```

**왜 이런 구조인가**: GitHub Pages는 정적 파일만 서빙하는 공개 사이트입니다. 사번·이름·평가결과 같은
개인정보를 여기 직접 올리면 저장소를 보는 누구나 볼 수 있습니다. 그래서 이름/사번/평가결과는
전부 **Google Sheets**에 두고, GitHub Pages는 화면(UI)만 담당하며 Google Apps Script를 통해
필요한 데이터만 그때그때 주고받습니다. 참고하신 `wmpeopleteam.github.io/recruitment` 채용 허브도
동일한 방식(Google Sheets + Apps Script)을 쓰고 있어 사내에서 이미 익숙한 구조입니다.

---

## 1. Google Sheet 준비

1. 업로드해주신 `현장소장_공사책임자_멘토_연락처.xlsx` 파일을 Google Drive에 업로드 → "Google Sheets로 열기"로 변환합니다.
   (시트 이름이 `평가대상`, `연락처`로 이미 되어 있어 별도 수정 없이 바로 씁니다.)
2. **⚠ 데이터 보완 필요** — 로그인이 안 되는 인원이 있습니다. 배포 전 반드시 채워주세요.
   - **임슬우** (변우종 님의 '동료' 평가자) — 연락처 시트에 아예 없습니다. 소속법인/사번/이메일 행을 추가해주세요.
   - **곽홍석** (박근홍 님의 '동료' / 장성욱 님의 '멘토' 평가자) — 이름/이메일만 있고 **개인고유사번이 비어있습니다.** 사번을 채워야 로그인됩니다.
3. 같은 스프레드시트에 `평가결과` 라는 이름의 빈 시트를 하나 더 추가해도 되고, 안 만들어도 됩니다 —
   Apps Script가 첫 제출 시 자동으로 만들어줍니다. (미리 만드는 경우 이름만 정확히 `평가결과`로 맞춰주세요.)

## 2. Apps Script 연결

1. 위에서 만든 Google Sheet를 열고 **확장 프로그램 → Apps Script**.
2. 기본 생성된 `Code.gs` 내용을 지우고, 이 저장소의 `apps-script/Code.gs` 내용을 전체 붙여넣기.
3. 왼쪽 톱니바퀴(프로젝트 설정) → **스크립트 속성**에 `ADMIN_CODE` 를 추가하고 원하는 관리자 접속 코드를 값으로 입력합니다.
   (설정하지 않으면 `Code.gs`에 적힌 기본값 `CHANGE-ME-1234`가 쓰이므로 **반드시 바꿔주세요**.)
4. 우측 상단 **배포 → 새 배포**
   - 유형: **웹 앱**
   - 실행 계정: 나(본인)
   - 액세스 권한: **전체(익명 포함)** — 사번 로그인 자체가 인증 역할을 하므로 이렇게 설정해야 GitHub Pages에서 접근됩니다.
5. 배포 후 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/xxx/exec`)을 복사합니다.
6. 최초 승인 화면이 뜨면 본인 Google 계정으로 권한을 허용해주세요(스프레드시트 접근용).

## 3. 사이트에 연결

`config.js` 파일을 열어 아래처럼 수정합니다.

```js
const CONFIG = {
  API_URL: 'https://script.google.com/macros/s/여기에-배포-URL/exec'
};
```

## 4. GitHub에 올리기

제가 이 대화 환경에서 사용자님 GitHub 계정에 직접 접근할 권한/연동이 없어서, 저장소 생성은
아래 절차로 직접 진행해주셔야 합니다(2분이면 됩니다). 코드는 이미 로컬 git 저장소로 전부
준비해두었습니다.

1. https://github.com/new 에서 저장소 이름 **`transition-review`**로 새 저장소 생성
   (사번·평가결과 등 민감정보는 코드에 없지만, 사내 전용으로 쓰실 거면 **Private**을 권장합니다.)
2. 아래 명령을 실행해 이 폴더 내용을 방금 만든 저장소로 push 하세요.

```bash
cd transition-review
git remote add origin https://github.com/<본인계정>/transition-review.git
git branch -M main
git push -u origin main
```

3. 저장소 **Settings → Pages**에서 Source를 `main` 브랜치 `/ (root)`로 설정하면
   `https://<본인계정>.github.io/transition-review/` 로 접속 가능합니다.
   (Private 저장소는 GitHub Pages를 쓰려면 GitHub Pro/Team/Enterprise 요금제가 필요합니다 —
   무료 계정이면 Public으로 두거나, 사내 서버에 정적 파일을 그대로 올려도 됩니다.)

## 5. 사용 방법

### 평가자
`index.html`(배포 후 사이트 첫 화면)에서 사번 입력 → 본인이 평가할 인턴 카드 목록이 뜹니다.
카드를 누르면 평가서가 열리고, 5개 영역(4점 척도) + 위험요인 체크리스트(3단계) + 종합의견 +
추천의견을 작성 후 제출합니다. 우수(4점)·미흡(1점)을 선택한 항목과 위험요인 '주의'/'중대'
항목은 구체적 근거 작성이 필수입니다. 제출 후에도 같은 카드를 다시 눌러 재작성·재제출하면
기존 응답이 최신 내용으로 덮어써집니다.

### 관리자
`admin.html`에서 접속 코드 입력 → 인턴별 4명 제출 현황을 한눈에 확인합니다.
"리포트 보기"를 누르면 해당 인턴에 대한 4인 평가 종합(영역별 점수·평균, 근거, 위험요인,
종합의견/추천의견)을 1페이지(코멘트가 많으면 2페이지) 리포트로 보여주며, 브라우저 인쇄
기능으로 PDF 저장이 가능합니다. "엑셀 다운로드"는 지금까지 제출된 모든 평가 원본 데이터를
xlsx로 내려받아 추가 데이터 가공에 사용할 수 있습니다.

## 6. 참고 — 원본 서식과 달라진 점

원본 워드 파일(`1__채용연계형_인턴_역량평가서.DOC`)은 멘토(1차)·현장소장(확정) 2인 체계로
설계되어 있었으나, 요청하신 대로 **현장소장/공사책임자/멘토/동료 4인이 동일한 문항으로 각자
독립 평가**하도록 재구성했습니다. 원본의 "멘토·현장소장 체크 2단계 이상 차이 시 조정" 로직은
2인 전제였던 규칙이라, 4인 체계에서는 관리자 리포트에서 **영역별 4인 점수와 평균을 나란히
보여주는 방식**으로 대체했습니다 — 최종 확정 점수·판정은 이 리포트를 근거로 인사부서 협의를
통해 정하시면 됩니다.

## 7. 알려진 제한사항

- 관리자 접속코드는 클라이언트에서 서버로 전송해 서버 측(Apps Script)에서 검증하지만,
  사내 소규모 도구 수준의 보안입니다. 민감도가 높다면 Google 계정 기반 인증(Apps Script를
  "Google 계정으로 로그인한 조직 내 사용자만" 접근 가능하도록 배포)으로 바꾸는 것을 권장합니다.
- 평가 데이터 백업은 Google Sheets 자체 버전기록 기능을 활용하세요.
